Tools · 01

LLM Wiki

A persistent knowledge base for a repository, written and kept current by the coding agent — Andrej Karpathy's LLM Wiki pattern.

  • Captures what the code alone doesn't show: architecture, decisions, postmortems, hacks, tech debt, runbooks.
  • Three layers: read-only sources → the wiki (cross-linked Markdown) → the schema that says when and how to update it.
  • Every session updates it as a side effect of normal work. [[wiki-links]] make it a graph you can browse in Obsidian.

Tools · 02

Merge Risk

Scores how risky a pull request is to merge, and gates the merge on the review that risk calls for.

  • Each file gets the tier of the riskiest rule it matches: path zones, patterns in added lines, PR size.
  • The PR gets the tier of its riskiest file. Never averaged — one risky file can't hide among a hundred safe ones.
  • Runs as a CI step: a label, a comment telling the reviewer what to look at, and a commit status that blocks the merge until the tier's approvals are in.

Tools · 03

Critics

Skeptical reviewer agents. Their job is to challenge the work hard, not approve it politely — approval should feel earned.

  • plan-critic — challenges the plan before leaving plan mode: simplicity first, unchecked assumptions, edge cases, scope, testability.
  • solution-critic — challenges the finished change before it's called done: reads the real diff, test quality, loose ends, complexity smells.
  • Re-invoked after every revision until the verdict is approved. The verdict is JSON, so tooling can parse it.

Tools · 04

Credential broker

Agents get access, never secrets.

  • The agent asks the broker for a specific permission instead of reading a secret.
  • The broker checks policy and issues a short-lived, narrowly scoped credential. The long-lived secret never leaves the vault.
  • Credentials expire on their own; every grant and every denial is logged.

Tools · 05

Project metrics

How a project is really going — over time, not as a snapshot.

  • Four measures on one timeline: velocity, quality, security, AI usage.
  • Separate charts on a shared time axis — hover a sprint to compare it across all four.
  • Shows whether AI-assisted delivery speeds things up without trading away quality or security.
